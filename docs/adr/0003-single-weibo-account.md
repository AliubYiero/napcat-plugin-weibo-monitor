# 0003 · 单微博账号模型

## 状态

已采纳 (2026-10-22)

## 背景与问题

WebUI 有「账号」页，但「账号」在多处含义模糊：页面分组、登录凭证、订阅归属。是否支持多微博账号并存是一个真实取舍：

- 多账号：每个账号一份 Cookie，订阅需要归属到账号，轮询按账号隔离，指令需要选择账号或按会话绑定账号，WebUI 需要账号切换器；
- 单账号：全插件唯一 Cookie，订阅是全局关系，指令不需要账号维度。

## 被放弃的方案与理由

- **多账号 + 指令带账号参数**：每条指令都要多带一个账号标识，用户理解成本上升；浏览器实例、限流与推送卡片也要按账号隔离。
- **多账号 + 默认账号**：指令省略时落到默认账号，行为依赖隐藏状态，排障时难以解释「为什么拉的是这个账号」。
- **按会话绑定账号**：订阅关系与账号归属耦合，同一博主在不同会话下可能对应不同账号，去重与水位线都要按账号拆开。

## 结论

- 全插件只有一个微博账号，由唯一 Cookie 承载；微博订阅（uid → 推送目标）不携带账号维度。
- 「账号页」只负责这个身份的凭证与运行依赖（Cookie / 浏览器）；订阅关系独立成「订阅」页。
- 代价：用户无法在一个插件实例里同时监听两个微博身份；确有需要时只能部署第二个插件实例。

## 该决策约束的文档与代码

- `CONTEXT.md` 的「微博账号」「微博订阅」「推送目标」。
- WebUI 页面划分：账号（凭证 / 浏览器）与订阅（关系管理）分离。
- 指令参数不包含账号维度。
