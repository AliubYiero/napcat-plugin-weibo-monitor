# 0009 · 已见缓存、内容类型开关与点赞/生日/置顶规则

## 状态

已采纳 (2026-10-26)

## 背景与问题

`mymblog` 首页不只有订阅博主的原创与转发, 还会插入本人的点赞条目、生日动态与置顶动态。旧实现有三处结构性缺口:

- 只按水位线 (最新一条 id) 认定新动态, 置顶/点赞插入会打乱首页顺序; 首页整体滚出水位线时只能丢弃整轮。
- 广告、置顶、转发都是无条件过滤, 用户无法选择接收哪些类型; 点赞与生日则完全没有进入推送链路。
- 点赞条目的 `user` 是原微博作者, 直接套用「作者 UID = 订阅 UID」会把它们全部淘汰; 即便放行, 外层身份也会错误地变成原博主。

同时, 点赞条目可能与历史点赞重复出现在首页, 仅用原微博 id 去重会导致「同一条微博在不同日期被再次点赞」永久丢失。

## 被放弃的方案与理由

- **继续扩展水位线 + `recentIds` 兜底**: 仍无法表达「同一原微博在不同日期被点赞」; 首页整体换页时只能靠交集数量猜是否重建, 语义不清晰。
- **为点赞单独请求 `likelist` 接口**: 增加一条易失效的接口与分页逻辑, 且无法复用首页已有的插入条目。
- **点赞用原微博 id 去重**: 同一条微博在不同日期被再次点赞会被误判为已见。
- **点赞外层仍用原微博作者**: 与「谁点了赞」的语义相反, 头像/昵称会指向原博主。
- **置顶无条件推送**: 置顶可能是很久以前的旧微博, 每次首页变化都会重复打扰; 纯按 id 去重又无法表达「置顶更新了才值得推」。
- **置顶只取一条**: 微博允许同时置顶多条, 只取一条会漏推。
- **广告/转发/置顶都做成独立布尔开关**: 字段膨胀, 且「广告」与其它类型是不同维度的否决关系; 统一为内容类型多选更易解释。
- **点赞日期缺失时拒绝推送**: 首页偶尔不给日期, 拒绝会漏掉真实点赞; 保留 `like:<id>:` 键即可安全去重。

## 结论

- 单 uid 的已见缓存最多保留 100 个去重键; 普通动态用动态 id, 点赞用 `like:<原微博 id>:<YYYY-MM-DD>`, 日期解析失败时日期段留空。
- 每轮成功拉取都把当前页全部有效条目写入缓存, 不论是否推送或被内容开关过滤; 新动态 = 键不在缓存中。
- `initialized === true` 且缓存非空、但当前页与缓存零交集时静默重建 (薄缓存也重建), 只写缓存、不推送; 缓存为空时正常推送后续首条。旧游标升级丢弃水位线与 `recentIds`, 保留暂停标记并重新基线化。
- 首绑与暂停恢复都用当前页全部条目建立基线, 不推送; 空列表同样标记 `initialized`。
- 新增全局多选 `weiboPushContentTypes`: `repost` / `like` / `ad` / `birthday`, 默认全选。原创始终推送; 广告是独立否决项, 关闭后连嵌套在转发里的广告也过滤; 空数组表示只推原创。
- 点赞条目跳过作者校验, 外层身份使用订阅博主; 原微博内容放入原微博块并以 `@` 展示原动态博主, 不输出原微博链接。原动态本身是转发时, 主文区按 `//@被点赞博主:转发理由` 展示, 卡片内博主名为链接, 转发块落到最原始博文。点赞信息栏不展示原动态来源; 转发块贴住卡片底部时以灰底承载底部留白。去重键带点赞日期, 点赞时间与首次拉取同日时补时分秒, 否则只显示日期。
- 生日动态只认 `source` 含「生日动态」; `page_info` 仅用于封面/标题/链接, 生日页链接绕过卡片对微博站内链接的抑制。
- 非点赞置顶走独立轨道: 与最新非置顶本人动态 (原创/转发/生日, 排除点赞) 严格比较, 只有更新才推; 多条置顶各自判断并按新 → 旧推送; 已在缓存中的置顶不重复推。
- 单轮不再限制推送数量; 拉取成功后先写缓存, 推送失败不重试。状态页的水位线只作为「最新已见 id」展示, 不参与判定。
